Hermes Guardian 0.2.0 adds Policy Lab and an operator policy workflow to the validated 0.1.0 plugin: Describe → Generate → Simulate → Review → Activate → Enforce.

Policy Lab uses the unchanged deterministic evaluator for hypothetical tool calls and seven fixed regressions. The offline builder is a deliberately limited language template with explicit clarification for unsupported requests. Optional general-language generation uses public Hermes structured model access; model outputs remain untrusted. Confirmed activation uses the public atomic settings API, an owner-only backup and readback/rollback handling. No separate API key or new dependency is required.

Verified on Hermes 0.23.1 / macOS arm64: 87 unit tests on Python 3.13 and 3.14; the original 194 real-runtime checks; additional product CLI, precedence, activation and Lab/live parity checks. See docs/VALIDATION.md for final counts and scanner cautions. The real 80-second demo uses the offline builder and scripted input for rehearsal; live provider inference and a human-recorded final video remain outstanding.

Not a sandbox. Project-only positive permissions and Git push approval are unsupported; Git commands block. Host automatic-approval settings, local path races/aliases, later argument rewriting and disabled/failed loading limit enforcement. Simulation predicts policy decisions, not tool success. Backups can contain local policy paths; audit records omit argument payloads. Storage failure can prevent activation/rollback; stop concurrent config editors during activation. Linux and broader UI/backend validation remain pending.
